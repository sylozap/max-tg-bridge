# MAX ↔ Telegram Bridge

Двусторонний мост между групповыми чатами MAX и Telegram. Участники пишут в привычном мессенджере и видят сообщения другой группы у себя. Один экземпляр моста может обслуживать несколько независимых пар чатов.

**Стек** · Python 3.11+, asyncio, aiogram, httpx, SQLite, Docker Compose.

## Что умеет мост

- Переносит текст с указанием автора, форматирование, фото, видео, аудио, документы и альбомы.
- Связывает копии с исходными сообщениями, чтобы сохранять контекст ответов и применять правки. Удаление исходника в MAX может удалить его копию в Telegram в пределах ограничений Bot API.
- Позволяет администраторам связывать группы, ставить пересылку на паузу и проверять её состояние командами в чате.

## Как устроена доставка

Адаптеры [Telegram](app/adapters/telegram.py) и [MAX](app/adapters/max.py) независимо опрашивают Bot API и приводят события к общей модели. [Ядро](app/core/bridge.py) направляет их в отдельную FIFO-очередь для каждой пары чатов и каждого направления. При временном сбое мост повторяет доставку в той же очереди, сохраняя порядок сообщений. Остальные очереди продолжают обработку.

[SQLite](app/storage/schema.sql) хранит связки чатов, соответствия исходников и копий и позиции опроса. Позиция сохраняется после обработки пакета. При повторном получении события мост пропускает уже обработанные сообщения и подавляет пересылку собственных копий. Сбой между отправкой и сохранением ID копии может привести к дублю.

## Быстрый запуск

Для реальной пересылки нужны два бота с правами на чтение и отправку сообщений в своих группах. Подготовьте токены и доверенный сертификат MAX по [инструкции](docs/operations.md), затем запустите мост из корня проекта.

```bash
test -f .env || cp .env.example .env
chmod 600 .env
# Заполните .env, включая MAX_CA_FILE=/certs/max-russian-trusted-root-ca.pem.
docker compose up -d --build
```

Когда мост запущен, получите ID обеих групп через `/id`. Настроенный администратор связывает их командой `/link <chat_id другой группы>` и проверяет доставку через `/status`.

[Настройка ботов и сертификата, запуск через systemd и настройка на VPS](docs/operations.md)

### Проверка без токенов

```bash
uv sync --locked --extra test
uv run --no-sync pytest -q
```

Тесты используют локальную SQLite и подставные адаптеры и проверяют порядок доставки, повторную обработку, восстановление после перезапуска и перенос ответов и вложений.

## Ограничения

- Мост использует Long Polling. Для production-интеграции MAX требует webhook. Доступность обновлений после простоя зависит от срока их хранения на стороне платформы.
- Telegram Bot API не сообщает об удалении исходных сообщений в группах. Для вложений и форматирования действуют ограничения обеих платформ. При недоступном вложении мост добавляет текстовую пометку.
- Текст обрабатывается в памяти. Вложения временно сохраняются на диске для пересылки. Перед связыванием чатов предупредите участников о зеркалировании.
